FILE DESCRIPTIONS
================================================================================

1. argocd-vks/argocd-vks.yaml
   ─────────────────────────────────────────────────────────────────────────
   - Kind: Cluster (cluster.x-k8s.io/v1beta2)
   - Wave: 0 (Initial resource creation)
   - Purpose: Defines VKS cluster to be provisioned
   - Contains:
     * Cluster network configuration (pods: 10.95.0.0/16, services: 10.96.0.0/12)
     * Topology with Kubernetes version (v1.36.2---vmware.2-vkr.3)
     * Control plane spec (1 replica, best-effort-medium)
     * Worker node pool (1 replica, best-effort-medium)
     * Storage class (vsan-default-storage-policy)
   - Namespace: kim-prod-vlryx
   - Status: Ready when cluster is fully provisioned
   - Typical Duration: 10-30 minutes
   - Annotation: argocd.argoproj.io/sync-wave: "0"

2. argocd-managedentity.yaml
   ─────────────────────────────────────────────────────────────────────────
   - Contains 3 Kubernetes resources:
   
   a) Role (argocd-k8s-sa-role)
      - Wave: 10
      - Purpose: Grant read access to cluster resources
      - Rules:
        * secrets (get, list, watch) in default namespace
        * configmaps (get, list, watch) in default namespace
        * clusters (get, list, watch) from cluster.x-k8s.io
      - Namespace: kim-prod-vlryx
   
   b) RoleBinding (argocd-k8s-sa-rolebinding)
      - Wave: 10
      - Purpose: Bind role to argocd-k8s-sa service account
      - Binds: argocd-k8s-sa → argocd-k8s-sa-role
      - Namespace: kim-prod-vlryx
   
   c) ManagedEntity (argocd-vks-managed)
      - Wave: 10
      - Kind: ManagedEntity (argocd-service.vsphere.vmware.com/v1alpha1)
      - Purpose: Register VKS cluster from Wave 0 to ArgoCD
      - Spec:
        * targetRef: Cluster argocd-vks (references Wave 0 cluster)
        * clusterName: argocd-vks-prod (display name in ArgoCD)
        * argoCDProject: default
        * namespaces: [] (all namespaces)
      - Namespace: kim-prod-vlryx
      - Status: Ready when cluster secret created in ArgoCD
      - Typical Duration: 2-5 minutes

3. argocd-app-of-apps.yaml
   ─────────────────────────────────────────────────────────────────────────
   - Contains one Kubernetes resource:
   
   a) Application (argocd-vks-app-of-apps)
      - Kind: argoproj.io/v1alpha1
      - Purpose: Orchestrate deployment of VKS cluster and registration
      - Source: GitHub repository (maxiepax/argocd)
      - Destination: kim-prod-vlryx namespace
      - Sync Policy:
        * Automated: true (prune: true, selfHeal: true)
        * Retry: Up to 5 times with backoff
      - Namespace: argocd
      - Syncs: Both argocd-vks.yaml and argocd-managedentity.yaml in wave order
   
4. argocd-vks-appproject.yaml
   ─────────────────────────────────────────────────────────────────────────
   - Optional AppProject (vks-cluster-registration), created separately
   - The Application uses default unless spec.project is changed
      - Kind: argoproj.io/v1alpha1
      - Purpose: Control access to cluster registration resources
      - Allowed Resources:
        * cluster.x-k8s.io/Cluster
        * argocd-service.vsphere.vmware.com/ManagedEntity
      - Destination: kim-prod-vlryx namespace
      - Namespace: argocd

================================================================================
DEPLOYMENT OPTIONS
================================================================================

Option 1: Direct kubectl (Simple, No App of Apps overhead)
─────────────────────────────────────────────────────────
kubectl apply -f argocd-vks/argocd-vks.yaml
kubectl apply -f argocd-managedentity.yaml
✓ Resources created immediately
✓ No Application orchestration
✗ Manual wave management

Option 2: App of Apps via ArgoCD (Recommended, Full orchestration)
──────────────────────────────────────────────────────────────────
kubectl apply -f argocd-app-of-apps.yaml
✓ Automatic wave sequencing
✓ Repeatable, version-controlled
✓ Self-healing, automatic sync
✓ Full GitOps workflow

================================================================================
WAVE EXECUTION SEQUENCE
================================================================================

WAVE 0 Timeline (10-30 minutes)
────────────────────────────────
T+0s      Cluster resource created from argocd-vks.yaml
T+5s      Topology controller observes
T+30s     VM provisioning starts (1 control plane, 1 worker)
T+2m      VMs boot, OS initialization
T+4m      Kubernetes components installed
T+5m      Worker joins control plane
T+7m      System pods deployed (CNI, coredns, etc)
T+10m     Cluster networking ready
T+12m     Health checks pass
T+30m     Cluster Status: Ready ✓

WAVE 10 Timeline (2-5 minutes, starts after Wave 0 completes)
─────────────────────────────────────────────────────────────
T+0s      Wave 0 completion detected
T+5s      Role created (argocd-k8s-sa-role)
T+7s      RoleBinding created
T+10s     ManagedEntity resource created
T+15s     VMware Operator observes ManagedEntity
T+20s     Service account validation begins
T+25s     RBAC binding verified (Condition: SupervisorServiceAccountBound=True)
T+30s     Cluster info fetched from Wave 0 (Condition: ClusterInfoFetched=True)
T+40s     Kubeconfig credentials generated
T+45s     Cluster secret created in ArgoCD namespace
T+50s     All conditions validated (Condition: Ready=True)
T+60s     ManagedEntity Phase: Ready ✓

TOTAL TIME: ~15-40 minutes (Wave 0 dominates, Wave 10 is fast)

================================================================================
SUCCESS INDICATORS
================================================================================

✅ Wave 0 Complete
   Command: kubectl get cluster argocd-vks -n kim-prod-vlryx
   Expected: PHASE=Ready

✅ Wave 10 Complete
   Command: kubectl describe managedentity argocd-vks-managed -n kim-prod-vlryx
   Expected: Phase=Ready, Condition Status: True

✅ Cluster Registered in ArgoCD
   Command: argocd cluster list
   Expected: argocd-vks-prod appears in list

✅ Cluster Secret Created
   Command: kubectl get secret cls-vks-kim-prod-vlryx-argocd-vks -n kim-prod-vlryx
   Expected: Secret exists with kubeconfig

================================================================================
ANNOTATIONS REFERENCE
================================================================================

Wave 0 Resources:
─────────────────
metadata:
  annotations:
    argocd.argoproj.io/sync-wave: "0"
    description: "VKS Cluster - Wave 0: Initial cluster creation"

Wave 10 Resources:
──────────────────
metadata:
  annotations:
    argocd.argoproj.io/sync-wave: "10"
    description: "Wave 10: Cluster registration resource"

ArgoCD syncs by wave number in ascending order, so:
- Wave 0 → Wave 1 → ... → Wave 10 → Wave 11 → ...
- Waits for all resources in a wave to complete before next wave
- Multiple resources in same wave are synced in parallel

================================================================================
CUSTOMIZATION GUIDE
================================================================================

To add more waves between creation and registration:

1. Add Wave 5 (Prerequisites):
   - Create namespace
   - Create persistent volumes
   - Create secrets/configmaps
   Add annotation: argocd.argoproj.io/sync-wave: "5"

2. Add Wave 15 (Applications):
   - Deploy apps after cluster registration
   Add annotation: argocd.argoproj.io/sync-wave: "15"

Example: Create a configuration before Wave 10:
metadata:
  annotations:
    argocd.argoproj.io/sync-wave: "8"

TROUBLESHOOTING QUICK REFERENCE
================================================================================

Problem: Wave 0 hangs
├─ Check: kubectl get cluster argocd-vks -n kim-prod-vlryx -w
├─ Cause: Infrastructure not available
└─ Fix: Check VMware vSphere logs, verify capacity

Problem: Wave 10 fails with "SA not bound"
├─ Check: kubectl get rolebinding argocd-k8s-sa-rolebinding -n kim-prod-vlryx
├─ Cause: RoleBinding not created or permissions denied
└─ Fix: Re-apply argocd-managedentity.yaml

Problem: ManagedEntity stuck in Pending
├─ Check: kubectl describe managedentity argocd-vks-managed -n kim-prod-vlryx
├─ Cause: Cluster not Ready (Wave 0 still running)
└─ Fix: Wait for Wave 0 to complete

Problem: Cluster not in ArgoCD cluster list
├─ Check: kubectl get secret cls-vks-* -n kim-prod-vlryx
├─ Cause: Cluster secret not created
└─ Fix: Check ManagedEntity status, restart operator if needed
